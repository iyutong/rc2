## 全方位重构：拆出 :rc2core 核心库（12:35，编译 + 单测通过）

目标：按键 / 摇杆的事件与数据获取「更好用、更好迁移」。做法是把协议层从界面里彻底剥出来，
做成零依赖的独立 Gradle 库模块。

### 模块结构
- `:rc2core`（namespace `local.rc2.core`，minSdk 29，**零第三方依赖**）：
  - `Rc2Controller` 唯一入口：`create(config)` / `start()` / `stop()` / `addListener()`，
    外加零分配 getter（`sticks() / flightMode() / isPressed() / isHeld() / packets()`）。
  - `Rc2Listener` 全 default 方法：onReady / onSticks / onButton / onFlightMode / onPacket / onKey / onError。
  - `Rc2Config` builder：pollIntervalMs(40) / buttonTimeoutMs(0=关) / packetRing(128) / callbackHandler / logger。
  - 数据类：`Sticks`（6 通道，命名访问器已按屏幕坐标取反）、`RcButton` 枚举（带 mask/中文标签）、
    `FlightMode` 枚举、`Rc2Packet`、`KeySample`、`Rc2State`（冻结快照）、`Rc2Log`、`KeyLabels`。
  - `internal/DjiProtocol`：唯一接触 Binder 的地方（transact 2 订阅 / 4 轮询 / 5 退订）。
  - `internal/ButtonCodec`：按键掩码、帧差异、hex。
- `:app`（namespace `local.rc2.xbox`）：
  - `MainActivity`：只做页面切换 + 生命周期 + Choreographer 帧循环。
  - `page/DashboardPage|RawPage|ProbePage`：各自持有控件，`tick()`/`refresh()` 只读 Rc2Controller。
  - `ui/Ui|UiLog|StickView|DialView`；`UiLog.SINK` 实现 `Rc2Log` 把核心日志接进界面环形缓冲。

### 关键设计点
- 回调默认在内部线程；传 `callbackHandler(new Handler(Looper.getMainLooper()))` 自动切主线程。
- 按键「变化才回调」；`onSticks` 按 pollInterval 周期回调；界面走 getter 轮询，避免 25Hz 分配。
- `Rc2State` 提供一次读全的冻结快照，`thread-safe`。
- 按键超时释放默认关闭（报文若只在变化时上报，开超时会误释放）。

### 构建坑
- `com.android.library` 的 plugin marker 在本机拉不到 → 改为 `id("com.android.library")` 不带版本，
  复用根工程 pluginManagement 已加载的 AGP 类路径（不要在 root 里 `alias(...) apply false`）。
- `:rc2core:assembleDebug`（打 AAR）会跑 `extractDebugAnnotations`，需要下载 lint-checks/intellij-core
  的 32MB jar，本网络 TLS 握手失败 → 会挂。`./gradlew :app:assembleDebug` 不触发该任务，正常。
  任务禁用无效（configuration cache 序列化阶段就会解析 androidLintTool）。

- `./gradlew :rc2core:testDebugUnitTest` 6 个用例全过（按键掩码、帧差异、挡位映射、摇杆归一化与钳位）。

## 修复：按 C1/C2 误报飞行模式变更（12:45，编译 + 7 个单测通过）

### 根因
`6/174` 报文的 b2 被两套解码共用：`ButtonCodec.mask()` 取 **bit2-3** 作为 C1/C2
（`(b2 & 0x0C) << 8`），挡位取 `b2 & 0x07`（含 bit2）。按 C1 时 b2 由 `0x00` 变 `0x04`，
挡位码由 0 变 4，两值映射到同一个 S，但 `handleMode` 用 **原始 b2** 比较是否变化，
于是每按一次 C1/C2 就打一条「飞行模式 S → S（b2=0x04）」。

### 修改
- `FlightMode`：新增 `code(int b2)` = `b2 & 0x03`（只取 bit0-1）；`fromByte()` 改走它；
  `fromCode()` 内部 `code & 0x03`，旧值 4/5/6 折叠后仍映射 S/N/C，行为不变。
- `Rc2Controller`：新增 `modeCode` 字段，`handleMode()` 改为比较挡位码，
  码相同时只静默更新 `modeByte`（供诊断），不记日志、不回调；
  日志格式改为「飞行模式 S → N（码 1 · b2=0x01）」。
  新增 `flightModeCode()` getter；`Rc2State` 增加 `flightModeCode` 字段。
  `modeSightings` 改为统计挡位码（0×12 1×3），不再统计会被 C1/C2 污染的原始字节。
- `DashboardPage.tickMode()`：诊断行改为「码 %d · b2 %02X · 已见」。
- `Rc2Listener.onFlightMode` 文档：明确 rawByte 的 bit2-3 是按键位，判挡位不要比 rawByte。
- 测试：新增 `c1c2BitsDoNotChangeFlightMode`（bit2/bit3 任意组合下挡位码与挡位都不变）。

### 结果
挡位只在真正的挡位切换（b2 低 2 位变化）时才产生日志与回调。

## 三份 APK 逆向 + 快门半按探针（13:45，编译通过）

用户给了三个从 RC2 提取的 APK，要求定位「拍照键半按」的输入/状态逻辑并给出可实施监听方案。

### 静态逆向结论（工具：aapt2 dump + build-tools dexdump + Python DEX 解析 + IL2CPP 元数据）
- **DJI Fly 1.21.10**（`dji.go.v5`，468MB / 22 dex / 仅 armeabi-v7a）：Lua flymodel 架构，按键调度在
  `com.uav.service.RcButtonService`，快门组件 `ShutterButtonWidget`；键值 schema 在
  `libsdk_key_value.so`。遥控器按键键名只有 `KeyRCShutterButtonDown` / `KeyRCShutterButtonLongPress`，
  全局搜 half/HalfPress 零命中 → **DJI Fly 没有半按模型**。
- **DJI Simulator 1.4.1**（`com.fly.simulator`，Unity IL2CPP）：`global-metadata.dat` 里有
  `ButtonStatus` 字段 `FocusButtonDown`（与 ShutterButtonDown 并列），命令集
  `RCCommandSet = PUSH_RC_CHANNEL_PARAM / PUSH_BUTTON_STATUS / SET_RC_CTRL_MODE / GET_RC_CTRL_MODE /
  SET_SIMULATOR_MODE / GET_SIMULATOR_MODE / SET_ANDROID_SYSTEM_STATUS`。它抢 USB accessory，
  会提示结束 DJI Fly 后台进程。
- **开发助手 com.dpad.fuli**（system UID + coreApp，`dpad` = DJI 带屏遥控器代号）：不打包
  `com.dji.protocol`，直接调系统框架 `ProtocolManager`；`ProtocolDict` 给出完整字典：
  RC cmdSet=6，174=BUTTON_PHY_STATUS，81=FIVE_KEYS(KEYCODE_STATUS)，100=DPAD_STATUS_SET，
  119=ANDROID_SYSTEM_STATUS，98/99 beep，108/109 wheel map，130/131 dpad role，132 CP scan。
  `ProtocalActivity` 是手发协议包页面，`ShellCommandActivity` 跑 shell（产线工具，勿依赖）。

**核心结论**：半按不进 6/174 位图、也不生成 Android 按键事件，被 MCU 直接转成相机对焦命令；
只有 RC 控制/模拟器模式下的 `ButtonStatus.FocusButtonDown` 才暴露该状态（且会断飞行链路）。
