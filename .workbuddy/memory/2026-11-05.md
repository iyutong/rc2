## 全项目 Java 代码分析（只读，未改代码）

项目定位：跑在 DJI RC2 遥控器（Build.DEVICE == "rc331"）上的 Android 应用，把遥控器实体按键/摇杆映射为全局虚拟 Xbox 手柄输入。applicationId/namespace 是 `local.rc2.xbox`，Java 主代码包名是 `local.rc2.controls`，Manifest 里 `android:process="com.dpad.fuli"`。

核心链路：McuReader（反射取 `protocol` Binder 服务，轮询 6 通道 + 订阅 6/174 按键包）→ ControlService（无障碍服务，记录/映射按键、生成 JSON 状态，20ms 一次写 abstract LocalSocket `rc2.xbox.global.v1`）→ LocalAdbStarter（连不上 socket 时经 127.0.0.1:5555 本机 adbd 发 shell 命令）→ GamepadBridgeMain（以 shell UID 2000 运行的 app_process32 进程）→ 注册 UHID 虚拟手柄 + 反射 `InputManager.injectInputEvent` 注入按键/摇杆。UI 为 MainActivity / DashboardView / GamepadTestActivity。

两处 sh：`LocalAdbStarter.java:50-55` 的整段 shell（旧 PID 清理、从 /init.environ.rc 补环境变量、unset LD_LIBRARY_PATH、CLASSPATH=APK、setsid app_process32 后台启动、日志与 sleep 1）；`GamepadBridgeMain.java:65` 的 `ProcessBuilder("/system/bin/sh", "/system/bin/hid", "-")`（AOSP hid 命令的 stdin 交互模式，只发 register 注册 VID 045e / PID 028e 的虚拟手柄，实际事件靠 injectInputEvent 注入）。/system/bin/hid 在新版 AOSP 是 shell 包装脚本，内部 `CLASSPATH=/system/framework/hid.jar exec app_process ... com.android.commands.hid.Hid`。

遗留问题：BridgeProbeMain 连的 socket 名 `rc2.xbox.uhid.v1` 与服务端 `rc2.xbox.global.v1` 不一致（连不上，且无入口）；BuildMode.MAPPER、MainActivity.edit() 未被引用；`pc` 偏好项已写入但无对应 UI；DashboardView 有 4 行无副作用的 held.contains()；两个 ExampleTest 仍是模板，断言包名为旧值。
